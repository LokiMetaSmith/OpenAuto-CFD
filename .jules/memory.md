* The meshing benchmark script `scripts/benchmark_meshing.py` compares OpenFOAM `snappyHexMesh` (STL surface pipeline) against `Gmsh` (STEP B-rep pipeline), evaluating wall-clock execution time, peak memory footprint, total cell count, and mesh quality metrics (max aspect ratio, non-orthogonality, and cell skewness).
* The PDF documentation pipeline uses `./build_pdf.sh` to automatically compile `TECHNICAL_REPORT.md` into `template.tex` via Pandoc to generate `publication.pdf`. Required dependencies are `pandoc` and `texlive-latex-base`.
* The WASM-based OpenSCAD generation (`export.js`) must explicitly mount `.svg` files into the virtual filesystem (using `instance.FS.writeFile`) to support `import()` statements within SCAD files.
* The OpenAuto-CFD framework is designed as a Multi-Physics Generative Framework using a solver-agnostic Physics Engine Factory. The `physics.type` field in the YAML configuration (e.g., 'cfd', 'em', or 'fea') dynamically determines the invoked solver driver (like OpenFOAM, openEMS, or CalculiX) and returns metrics in a unified format for the optimizer.
* In `build123d` v0.13.0+, `Helix` generates a `Curve` and is no longer a Builder-compatible object that can be added directly inside `BuildPart`. To use it in a sweep operation, instantiate it within a `b3d.BuildLine()` context and use `.wire()` on the resulting path object (e.g., `b3d.sweep(sections=..., path=path.wire(), is_frenet=True)`). Using `is_frenet=True` is critical to ensure the generated helical meshes are watertight and free of non-manifold edges.
* Off-screen 3D visualization rendering with PyVista requires setting `pv.OFF_SCREEN = True` and using `pv.Plotter(off_screen=True)` to avoid X server GUI display errors in headless container environments.
* The `GmshDriver` module (`optimizer/gmsh_driver.py`) provides direct STEP-to-Mesh 3D volume meshing for OpenFOAM using the Gmsh Python API, converting B-rep STEP models directly into `.msh` volume meshes.
* In EM simulation configs (YAML), the `geometry` block uses the key `scad_file` to specify the parametric model path, ensuring compatibility with the `main.py` entry point's parser.
* `update_blockMesh` in `FoamDriver` (`optimizer/foam_driver.py`) dynamically adjusts background grid cell size based on `channel_gap_mm` to ensure 4 to 5 base cells fit across narrow helical channel gaps.
* The OpenAuto-CFD multi-physics framework utilizes a `PhysicsDriver` base class (`optimizer/physics_driver.py`). All specific physics solvers, such as `FoamDriver`, `OpenEMSDriver`, and `FeaDriver`, must inherit from this class and be instantiated via the `PhysicsEngineFactory`.
* In `optimizer/simulation_runner.py`, the workflow for EM physics includes a step to generate individual STL files for each entry in the configuration's `part_options` (e.g., copper, substrate, ports) using the `ScadDriver` before invoking the physics driver.
* The CAD driver interface includes `generate_interactive_html()` in `CadDriverBase`, embedding STL models as base64 strings inside self-contained Three.js WebGL HTML files for interactive 3D browser viewing.
* The test module `test/test_cad_parity.py` evaluates geometric volume and bounding box parity between legacy OpenSCAD output and native `build123d` models to ensure geometric equivalence within 1.5% tolerance.
* The Model Context Protocol (MCP) server module is located at `optimizer/mcp_server.py` and provides a stdio interface using `FastMCP`/`MCPServer` (compatible with `mcp` v1 and v2). It exposes MCP tools (configuration listing, simulation execution, harness status querying, run details, schema surrogate loop execution, parameter validation, parameter suggestions, dataset export, and GenCAD tools like `gencad_retrieve_from_physics`, `gencad_synthesize_script`, `gencad_retrieve_from_image`, `gencad_sample_diverse`), MCP resources (`config://`, `log://latest`, `schema://notes`), and MCP prompts (`analyze_simulation_results`, `schema_surrogate_reasoning`). It can be invoked via `python -m optimizer.mcp_server`.
* When invoking pytest in the container environment, use `python3 -m pytest` instead of just `pytest` to ensure tests execute against the correctly configured Python module path and installed dependencies, bypassing potential virtual environment shim issues.
* The `FoamDriver` class (`optimizer/foam_driver.py`) supports Jinja2 templating for OpenFOAM dictionary configuration files. It accepts a `template_kwargs` dictionary argument to dynamically inject and tune parameters such as `nSurfaceLayers`, `maxNonOrtho`, and `includedAngle` directly into the templates.
* `_clamp_scalar_fields` in `FoamDriver` (`optimizer/foam_driver.py`) sanitizes initial OpenFOAM scalar field values ($k \ge 10^{-6}, \epsilon \ge 10^{-6}, \nu_t \ge 10^{-7}$) prior to simulation execution to prevent numerical instability and solver divergence.
* The framework utilizes `optuna` in `optimizer/auto_tuner.py` (via the `DryMeshObjective` class) to perform 'Dry-Mesh' optimization. This evaluates meshing quality and manufacturability by running OpenFOAM's `blockMesh` and `snappyHexMesh` procedures without executing the full CFD solver.
* The framework integrates Finite Element Analysis (FEA) for motion and vibration via the `FeaDriver`. It leverages CalculiX (ccx) and gmsh for solving and meshing (currently utilizing mocked Python scripts for execution) to extract core metrics like `max_displacement_mm` and `max_von_mises_stress_MPa`.
* Phase 2 of `GenCADDriver` (`optimizer/gencad_driver.py`) introduces off-screen 2D STL rendering (`render_stl_to_image_array`), a PyTorch CNN vision encoder (`CADVisionEncoder`), and image-conditioned cross-modal CAD retrieval and generation (`retrieve_cad_from_image` and `generate_cad_from_image`) registered in `CADAgentToolRegistry` (`optimizer/cad_agent_tools.py`).
* In `optimizer/foam_driver.py`, when programmatically updating `locationInMesh` using regex, the pattern must account for both explicit coordinates `(x y z)` and Jinja2 template variables (e.g., `{{ location_in_mesh }}`). Failing to match the template syntax causes `snappyHexMesh` to use a default or invalid internal point outside the fluid volume, leading to missing patches.
* The OpenAuto-CFD framework implements a detailed failure feedback loop: `FoamDriver` parses `checkMesh` and solver logs to capture specific geometric/physical issues (e.g., non-orthogonality, diverging residuals) into `self.last_error_details`. This information is propagated via `simulation_runner.py` into the `metrics['details']` field, which the `LLMAgent` incorporates into prompts along with specific heuristic repair instructions for the LLM.
* Running `export.js` via Node.js requires a prior `npm install` to ensure dependencies like `@scalenc/stl-to-png` are present in the `node_modules` directory.
* When interfacing with `FoamDriver` programmatically (e.g., for auto-tuning or custom scripts), the correct API methods to prepare the OpenFOAM environment and generate the mesh are `prepare_case()` and `run_meshing()`. Do not use `initialize_case()` or `_generate_mesh()`.
* The `GenCADDriver` (`optimizer/gencad_driver.py`) includes `CADSequenceTokenizer` for tokenizing/deserializing `build123d` CAD AST command sequences and `GenCADTransformerModel`, an autoregressive PyTorch Transformer encoder-decoder that generates discrete CAD command sequences from CFD physics performance vectors with automatic CPU/CUDA fallback.
* The distributed job manager (`optimizer/job_manager.py`) and worker (`optimizer/worker.py`) implement worker heartbeat tracking (`record_heartbeat`) and automatic dead-worker stale job recovery (`requeue_stale_jobs`) when worker nodes fail or time out.
* The `OpenEMSDriver` dynamically generates a Python script (`run_em_simulation.py`) based on the YAML configuration. It supports mapping multiple STLs (e.g., `copper.stl`, `substrate.stl`) to specific materials and automates port setup by calculating coordinates from the bounding boxes of dedicated port STLs. It extracts EM metrics from `s_parameters.csv` and implements physically accurate VTK export by converting raw HDF5 field data using `h5py`.

* The `FeaDriver` (`optimizer/fea_driver.py`) evaluates 3D structural metrics including von Mises stress (`max_von_mises_stress_MPa`), displacement (`max_displacement_mm`), and factor of safety (`factor_of_safety`) for STEP and STL models under pressure loads.

This prevents validation failures and infinite retry loops caused by missing parameters or malformed schema dictionaries bleeding into the validation logic.

To map multiple unique geometries (e.g., `corkscrew_fluid`, `corkscrew_wall`) to the same resulting boundary patch (e.g., `corkscrew`), use the `name` attribute inside the `patchInfo` sub-dictionary within the `refinementSurfaces` block.

* The project adapts the Schema design pattern to a unified multi-physics (CFD, FEA, EM) optimization loop where the state vector is composite: $S_t = [G, \mathbf{F}, \mathbf{M}, \mathbf{E}]$, and action $A_t$ represents parametric mutations. The virtual world model `world_model.py` dynamically maintains an LLM-synthesized `step(state, action)` function acting as a fast physics surrogate, with backtesting against solver ground-truth recorded in `timeline.jsonl`.
